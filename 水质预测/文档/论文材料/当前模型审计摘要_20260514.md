# 当前模型审计整理（2026-05-14）

## 1. 先说结论

当前工作区主链路的正式训练脚本是 `脚本/04_模型训练/05_train_full_station_models.py`，主结果文件位于：

- `结果/正式结果/full_station/full_station_training_metrics.csv`
- `结果/正式结果/full_station/full_station_predictions.csv`
- `结果/正式结果/full_station/full_station_feature_manifest.csv`

当前版本的**主验证方式是严格时间外推**，不是随机划分，也不是空间留站点外推：

- 训练集：2014-2022
- 测试集：2023-2024

当前版本还有一个非常重要的科学风险：

- `f1_process` 和 `f3_fusion` 使用了**同期其他水质指标**作为输入特征。
- 没有使用“上一次采样值”“上个月值”“滚动滞后值”这类历史水质特征。
- 因此，当前代码跑出来的高分，尤其是 TN 接近 `R2 = 0.99` 的结果，**不能直接解释为中长期预测能力**，更像“同日协变量辅助回归”。

## 2. 一个样本到底是什么

当前样本不是“站点×月平均”，也不是“站点×天网格”。

当前主表里：

- `sample_id = 站点 × 日期`
- `obs_id = 站点 × 日期 × 水层`

因此，**一个建模样本 = 某站点某次采样在某一水层上的一条观测**。

示例：

- `sample_id = DM1_20140102`
- `obs_id = DM1_20140102_surface`

## 4. 数据划分方式

当前主脚本只做了这一种 split：

```text
train: 2014-2022
test : 2023-2024
```

也就是：

- 不是 `train_test_split(random_state=42)` 随机划分
- 不是留站点空间外推
- 是**严格时间外推**

这意味着当前 `R2` 的难度高于随机划分，但也更符合“未来时间预测”的设定。

## 5. 当前最终特征列表

- 例如预测 TN 时，不用 `tn_mg_l`，但会用 `chla_ug_l / tp_mg_l / secchi_depth_m`。

### 历史水质特征是否使用

当前版本：

- **没有**使用“上个月 Chl-a / 上个月 TN”
- **没有**使用 lag1 / lag2 / rolling 特征
- 用的是**同期其他水质协变量**

这点对研究解释极关键。

## 6. 遥感提取细节

### Sentinel-2

- 传感器：Sentinel-2 SR Harmonized
- 产品：`COPERNICUS/S2_SR_HARMONIZED`
- 时窗：采样日前 `7` 天到采样日
- 空间 buffer：`90 m`
- 云处理：`SCL + cloud probability + QA60`
- 聚合方式：`median` 后做 buffer 内均值
- 光谱/指数：`B2, B3, B4, B5, B6, B8, B8A, B11, B12, NDWI, MNDWI, NDCI, NDTI`
- 严格有效阈值：`valid_pixel_count >= 5`

### Landsat

- 传感器：Landsat 8 / Landsat 9
- 产品：`LANDSAT/LC08/C02/T1_L2` + `LANDSAT/LC09/C02/T1_L2`
- 时窗：采样所在自然月
- 空间 buffer：`150 m`
- 云处理：`QA_PIXEL + QA_RADSAT`
- 聚合方式：`median` 后做 buffer 内均值
- 光谱/指数：`blue, green, red, nir, swir1, swir2, ndvi, ndwi, mndwi, ndti`
- 严格有效阈值：`clear_pixel_count >= 3`

### 有效影像/有效像元统计

Landsat：

- `landsat_image_count` 平均 `4.65`
- `landsat_clear_pixel_count` 中位数 `56`
- `landsat_has_images = 98.39%`
- `landsat_strict_valid_gee = 65.74%`

Sentinel-2：

- `s2_image_count` 平均 `5.83`
- `s2_valid_pixel_count` 中位数 `0`
- `s2_has_images = 56.41%`
- `s2_strict_valid = 18.01%`

直接结论：

- Landsat 质量总体明显好于 S2。
- S2 存在大量空值或低有效像元样本。
- 你怀疑的“`valid_count` 太低、遥感信息弱”在当前版本里**是成立的**。

## 7. 模型细节

当前模型为：

- `XGBRegressor`

参数：

- `n_estimators = 400`
- `max_depth = 4`
- `learning_rate = 0.05`
- `subsample = 0.8`
- `colsample_bytree = 0.8`
- `objective = reg:squarederror`
- `random_state = 42`
- `n_jobs = 4`

当前版本：

- 没有 `GridSearch`
- 没有 `Optuna`
- 没有正式调参流程

## 8. 评价指标

当前主脚本直接按测试集全部样本计算：

- `r2_score(y_true, y_pred)`
- `RMSE = sqrt(MSE)`
- `MAE`
- `NSE`

当前主脚本**没有单独写出 Bias**，但可以由预测表计算。  
我已核算过，Bias 在不同目标/特征组之间差异较大，尤其 Chl-a 和 Secchi 更明显。

## 9. 当前结果怎么读

### 当前代码直接跑出的“最高分”

最高分主要来自 `f1_process / f3_fusion`：

- TN-middle `f1_process`: `R2 = 0.9964`, `RMSE = 0.0194`
- TN-bottom `f1_process`: `R2 = 0.9949`
- TN-surface `f1_process`: `R2 = 0.9947`

这些结果非常高，但原因并不神秘：

- 当前过程特征里用了**同期其他水质变量**
- 因而这更像“同日多指标回归”，不是纯粹中长期预测

### 更值得信的“无遥感泄漏基线/遥感-only”结果

baseline 最好：

- TP-surface baseline: `R2 = 0.4127`, `RMSE = 0.0524`
- TN-surface baseline: `R2 = 0.4001`, `RMSE = 0.3814`
- SD-surface baseline: `R2 = 0.3778`, `RMSE = 0.8969`

remote-only 最好：

- TN-surface remote-only: `R2 = 0.2107`, `RMSE = 0.4375`
- SD-surface remote-only: `R2 = 0.2020`, `RMSE = 1.0158`
- Chl-a-surface remote-only: `R2 = 0.0663`, `RMSE = 6.1344`

### “哪个指标 R2 = 0.2”必须怎么理解

当前版本里，接近 `R2 = 0.2` 的结果主要是：

- TN-surface `f2_remote`: `R2 = 0.2107`
- SD-surface `f2_remote`: `R2 = 0.2020`
- Chl-a-middle `baseline`: `R2 = 0.1852`

因此：

- `TN 的 0.2` 说明遥感对总氮有一点信息，但仍偏弱
- `SD 的 0.2` 对透明度而言是中等偏弱但不算完全没信号
- 当前版本**没有出现一个“Chl-a = 0.2”的正式结果**
- 当前版本 **TP 也没有“0.2 左右”的典型结果**

所以你说得对：`TP 的 0.2` 和 `Chl-a 的 0.2` 绝对不能混着解读。

## 10. 你目前怀疑的问题，逐条判断

### 问题 1：遥感特征几乎没信息

基本成立。

证据：

- `f2_remote` 平均 `R2 = 0.0175`
- Chl-a 的 remote-only 很差
- S2 严格有效率只有 `18.01%`

### 问题 2：你在做严格时间外推

成立。

- 当前主 split 就是 `2014-2022 train / 2023-2024 test`

### 问题 3：不同海区机制混合

成立。

- 当前主模型把 94 个站点直接 pooled
- 只用了 `water_zone_code` 作为类别位置信息
- 没有分海区建模，也没有显式交互机制

### 问题 4：月尺度样本太少

不完全成立。

- 每站每年每层平均样本数约 `10.5-10.8`
- 中位数是 `12`
- 所以样本频率大致就是“接近月采样”

问题不在于“完全太少”，而在于：

- 采样不是规则月序列
- 遥感有效样本不足
- 没有历史滞后结构

### 问题 5：没有历史滞后特征

成立。

- 当前代码没有滞后水质特征
- 这对中长期预测尤其关键

### 问题 6：valid_count 太低

成立，尤其是 S2。

- `s2_valid_pixel_count` 中位数 `0`
- `s2_strict_valid` 只有 `18.01%`

## 12. 最后一句判断

当前工作区这版代码，**最主要的问题不是模型不够复杂，而是任务定义和特征定义混在一起了**：

- 你名义上在做“中长期预测”
- 但当前主模型却用了“同期其他水质指标”

所以现在最值得做的，不是先继续卷更复杂模型，而是先把下面三件事切干净：

1. 去掉同期水质协变量，恢复真正可解释的预测设定
2. 补上历史滞后特征，再重跑时间外推
3. 单独把遥感-only 结果做成敏感性分析，而不是让它和同期协变量混在一起
