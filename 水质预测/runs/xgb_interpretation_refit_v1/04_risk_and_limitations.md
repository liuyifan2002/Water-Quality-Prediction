# XGBoost 受控复现风险与限制

1. 原始20折模型和逐折 median imputer从未保存，因此只能重新拟合，不能恢复原二进制对象。
2. 保留的隔离环境当前报告 Python 3.11.9、XGBoost 3.2.0、scikit-learn 1.9.1、NumPy 2.4.6、pandas 2.3.3；但原 registry 没有逐折记录完整版本，也没有不可变 lockfile。这些版本是现场证据，不是每折运行时环境的直接证明。
3. 原训练脚本当前可计算 SHA-256，但相关脚本在现有工作树中缺乏可追溯的正式 Git 提交版本号。必须把当前脚本哈希随复现资产固化。
4. XGBoost CPU多线程、底层库或硬件差异可能造成浮点级差异；因此严格一致与近似一致采用预先分开的门槛。
5. 正式主表、配置、manifest和预测文件当前均存在，但没有原运行时统一的输入快照清单。复现前必须再次记录文件哈希；哈希变化则停止。
6. Family V2 的部分 `06_preflight.md` 标题或协议文字存在复制遗留错误，不能把其中的任务名称当作唯一事实来源；应以任务 manifest、registry、训练脚本和逐样本预测交叉确认。
7. 预测 CSV 保存精度较高，但它仍是比较基准而非模型资产；不得由预测反向拟合替代模型。
8. 即使预测达到严格一致，树结构二进制是否逐字节一致也不是验收目标；解释可关联性的核心是相同输入、参数、软件环境和逐样本预测一致性。
9. 若仅达到近似复现，SHAP值可能因树结构微小差异而改变。必须额外验证跨折重要性排名和ALE曲线稳健性后才能用于论文主文。
10. 本轮没有运行XGBoost、TabICLv2、TabPFN、TabM、SHAP或ALE，也没有修改正式预测成果。
