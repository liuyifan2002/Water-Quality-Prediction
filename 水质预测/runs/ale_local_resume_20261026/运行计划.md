# 本机一维 ALE 续算计划

目标：按 `TABICLV2_SLIM_EXPLAINABILITY_V2_ALL10` 既定 P1 单查询协议，续算十任务 fold_1 的一维 ALE。结果仅表示 P1 函数的局部解释；历史预测复现资格、V1 失败记录与正式模型结果保持原样。

## 阶段与验收

1. `PRECHECK`：确认原始 Python 环境、checkpoint、77 特征、任务登记、V1 已完成 SHAP 与 V2 暂停状态；复核分箱边界哈希故障。
2. `HASH_FIX`：只修正 V2 ALE 脚本对原始 CSV 浮点边界的读取精度；原脚本副本和 SHA256 保存在本目录。以现有 V1 查询清单证明修正后的边界哈希与保存值一致，不运行模型完成此检查。
3. `DASHBOARD`：启动项目已有的本机只读面板 `http://127.0.0.1:8765`；以 `/health` 与 `/api/status` 验证可读，面板从 V2 进度文件、注册表和已落盘结果汇总真实状态。
4. `ALE_FIRST`：复用 V1 已完成的 TN 表层、TN 底层和 TP 底层核心 SHAP，先做支持度审查，再逐条计算满足门槛的一维 ALE。保留 SQLite 检查点，失败单元单独记录。
5. `ALL10_QUEUE`：启动已有 V2 串行调度器，补齐其余任务的核心 SHAP 前置条件，并续算最多每任务两条 ALE。队列遵守单 GPU、已有结果哈希复用、任务边界暂停机制。
6. `REVIEW`：核对曲线数量、数值重复性、样本和站点支持度、日志与面板状态。`COMPUTED` 只表示计算完成，不直接宣称科学解释通过。

## 停止条件

- 输入、checkpoint、特征顺序或上下文哈希不一致。
- 活跃 GPU 解释队列发生冲突。
- CUDA 非法内存访问等硬故障重复出现。
- 分箱样本数或独立站点数未达到既定阈值。

本计划不重新训练模型，不修改正式预测、split、77 特征清单或既有 V1 结论。
