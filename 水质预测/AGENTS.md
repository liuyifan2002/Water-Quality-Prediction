# 项目规则（AGENTS）

本文件定义本项目后续所有 AI / Codex / 协作者在修改代码、补充实验、整理结果时必须遵守的规则。

## 1. 项目正式主链说明

- 本项目当前**正式主链**为：**全站点三水层 `full_station` 主链**。
- 正式主链目标是围绕香港近岸 2014-2024 年水质观测，构建 `Chl-a / Secchi / TN / TP × Surface/Middle/Bottom` 的正式建模、汇总和论文输出流程。
- `Chl-a` 优化、站点独立建模、分海区建模、滚动 CV、生态增强等均属于**扩展实验**，不得和正式主链混为一体。
- 早期表层 `v0` 脚本与结果仅作为历史留档，统一放入 `脚本/历史版本/` 或 `归档_历史版本/`。

## 2. 目录职责边界

- `配置/`
  - 存放路径配置、正式主链配置、历史配置。
- `数据/原始数据/`
  - 存放原始输入、原始下载文件，不做人工改写。
- `数据/中间数据/`
  - 存放中间过渡文件、临时 merge 文件。
- `数据/处理后数据/正式主表/`
  - 存放正式主链关键输入表。
- `数据/处理后数据/衍生版本/`
  - 存放增强版、敏感性版、扩展实验版数据。
- `数据/处理后数据/诊断数据/`
  - 存放诊断专用数据。
- `脚本/01_数据准备/`
  - 原始水质、站点、基础样本准备。
- `脚本/02_特征构建/`
  - 遥感 merge、ERA5、降雨、潮汐、夜光与建模特征表构建。
- `脚本/03_GEE遥感导出/`
  - GEE JavaScript 导出脚本。
- `脚本/04_模型训练/`
  - 正式主链训练脚本与扩展实验训练脚本。
- `脚本/05_诊断分析/`
  - 诊断、残差、峰值、自相关、覆盖度分析。
- `脚本/06_结果汇总与绘图/`
  - 汇总、论文图、SHAP、PPT 结果输出。
- `脚本/历史版本/`
  - 不再作为正式入口的旧脚本。
- `结果/正式结果/`
  - 仅存放正式主链输出。
- `结果/扩展实验/`
  - 存放扩展实验输出。
- `结果/诊断结果/`
  - 存放诊断分析输出。
- `结果/论文图表/`
  - 存放论文级图版与 SHAP 图版。
- `结果/PPT材料/`
  - 存放演示图与 PPT。
- `文档/论文材料/`
  - 存放论文文字、结果解读、研究流程说明等。
- `归档_历史版本/`
  - 存放过期输出和外部杂项。
- `待确认_未归类/`
  - 归属不明确的文件先放这里，不要硬塞。

## 3. 新增代码放置规则

- 新增功能前，**必须先判断属于哪个模块**。
- 新增功能前，先回答以下 5 个问题，再给出文件改动计划：
  1. 这个功能属于哪个目录？
  2. 是否属于正式主链、扩展实验、诊断分析，还是论文输出？
  3. 是否需要新增脚本？如果需要，脚本名称是什么？
  4. 是否会影响已有正式主链结果？
  5. 需要更新哪些文档？
- **回答完后，再写代码。不要直接写代码。**
- 不允许把数据处理、特征构建、模型训练、评估绘图、论文输出写在同一个脚本里。
- 新增脚本应放入对应模块目录，不允许继续在 `脚本/` 根层堆放。

## 4. 禁止事项

- 不允许修改模型算法、训练参数、特征构造逻辑和绘图风格，除非用户明确要求。
- 不允许直接修改正式主链逻辑，除非先说明影响范围。
- 不允许把正式主链脚本和历史实验脚本继续混放。
- 不允许把临时实验结果放入正式结果目录。
- 不允许把论文文字、图片、CSV 结果、PPT 资产继续混在同一目录。
- 不允许新增“随手命名”的脚本，例如：
  - `test.py`
  - `new.py`
  - `final.py`
  - `修改版.py`
- 不允许通过改路径整理来偷偷改变输出结果。

## 5. 修改前检查流程

每次动手前，至少完成以下检查：

1. 确认当前任务属于正式主链、扩展实验、诊断分析还是论文输出。
2. 确认目标文件是否已经存在于正确目录。
3. 检查是否会影响 `结果/正式结果/full_station/`。
4. 检查是否存在历史版本脚本可复用，而不是重复造轮子。
5. 如文件归属不确定，先放入 `待确认_未归类/`。

## 6. 修改后验证流程

每次修改后，至少执行以下验证：

1. 检查路径是否仍然存在。
2. 检查主脚本输入输出路径是否正确。
3. 对 Python 脚本做语法检查。
4. 对正式主链关键 CSV 核对行数、列数和字段名。
5. 如果修改触及正式主链，确认正式结果是否仍可复现。

## 7. 文件命名规范

- 脚本命名：使用有序编号 + 英文描述，例如：
  - `04_build_model_table.py`
  - `05_train_full_station_models.py`
- 结果目录命名：
  - 正式主链固定放入 `结果/正式结果/full_station/`
  - 新实验必须放入 `结果/扩展实验/实验名称_日期/`
- 文档命名：
  - 中文说明文稿使用中文命名
  - 结构化说明文件放入 `文档/`
- 配置命名：
  - `项目路径配置.json`
  - `正式主链配置.json`
  - `历史_v0配置.json`

## 8. 实验结果保存规范

- 正式主结果只允许由正式主链脚本生成。
- 不允许把临时实验结果、调参中间结果、失败试跑结果写入 `结果/正式结果/`。
- 扩展实验统一放入 `结果/扩展实验/实验名称_日期/` 或对应扩展实验子目录。
- 诊断输出统一放入 `结果/诊断结果/`。
- 论文图版统一放入 `结果/论文图表/`。

## 9. 旧脚本归档规范

- 不再作为主入口的旧脚本，移入 `脚本/历史版本/`。
- 旧结果、过期 CSV、smoke 输出移入 `归档_历史版本/过期输出/`。
- 不删除历史文件，只归档。
- 归档后如仍需引用，应在文档中说明用途。

## 10. Git 提交规范

- 目录迁移优先使用 `git mv`。
- 提交信息应准确说明本次变更属于：
  - 结构整理
  - 路径修复
  - 文档更新
  - 扩展实验
  - 正式主链修订
- 每次修改后，必须更新：
  - `文档/文件迁移记录.md`
  - 或 `文档/后续重构计划.md`
- 如果同时修改正式主链脚本和扩展实验脚本，提交说明中必须明确区分影响范围。

## 11. 特别规则

- 新增功能前，必须先判断属于哪个模块。
- 不允许把数据处理、特征构建、模型训练、评估绘图、论文输出写在同一个脚本里。
- 不允许把临时实验结果放入正式结果目录。
- 不允许直接修改正式主链逻辑，除非先说明影响范围。
- 不允许新增“随手命名”的脚本，例如 `test.py`、`new.py`、`final.py`、`修改版.py`。
- 新实验必须放入 `结果/扩展实验/实验名称_日期/`。
- 正式主结果只允许由正式主链脚本生成。
- 每次修改后必须更新 `文档/文件迁移记录.md` 或 `文档/后续重构计划.md`。
- 如果不确定文件归属，先放入 `待确认_未归类/`，不要硬塞进现有目录。
